# MpChain 复现包

串行稀疏激活：N 个参数独立的小模型组成专家池，共享一块定长外部记忆，一次预测执行最多 T 次串行调用，每步由前一步的路由硬选择执行者。

代码按论文的实验顺序拆成 7 个双击即可运行的 `.cmd`。每个文件都会先切到自身所在目录，产物写在同目录下。

## 环境

```
pip install -r requirements.txt
```

Windows + Python 3.10 以上。训练需要 NVIDIA GPU；主模型在 8 GB 显存的笔记本卡上可以跑（batch 128 约占 6.6 GB），论文里的数字是在 RTX PRO 6000 上测的。

把整个目录放在**纯英文路径**下（`D:\mpchain_repo` 这样），批处理里没有对空格和中文做转义。

## 七个文件

| 文件 | 做什么 | 耗时 | 产物 |
|---|---|---|---|
| `0_检查环境.cmd` | 打印 Python / torch / CUDA 版本，检查两个数据文件在不在，并试导入全部模块 | 几秒 | 屏幕输出 |
| `1_重建数据_可选.cmd` | 从原始 UN 语料重建 `data/un_sub.npz`。**默认跳过**，因为数据已随包提供 | 约 1 分钟 | `data/un_sub.npz` |
| `2_训练主模型.cmd` | 训练主模型（N=40, d=128, T=6, batch=128, lr=1e-3, 100k 步） | 云端约 3 小时 / 笔记本约 14 小时 | `ck_seed0.pt` |
| `3_训练两个基线.cmd` | 依次训练 token-level MoE 与 12 层稠密 Transformer（同数据、同步数、同 batch） | 各数小时 | `ck_moe_s0.pt`、`ck_tf_s0.pt` |
| `4_评测与统计.cmd` | BLEU-2 与逐 token 准确率（所有模型跑同一批 500 句）、句末截断口径、跨 seed 均值±标准差、配对置信区间 | 约 5 分钟 | `evaldump/*.jsonl` + 屏幕表格 |
| `5_机制实验.cmd` | 评估期消融（早停 / 固定步数 / 槽位屏蔽）、路由敏感性（五档扰动）、路由置换对照、T=3 与 T=6 配对检验 | 约 20 分钟 | 屏幕表格 + `route_v2.json` |
| `6_效率基准.cmd` | 每 token FLOPs（两种架构同一口径）与墙钟阶梯（eager → 静态 buffer → compile → CUDA graph） | 约 10 分钟 | 屏幕表格 |

`2_` 和 `3_` 支持传参指定种子，论文里每个配置用了 0/1/2：

```
2_训练主模型.cmd 0
2_训练主模型.cmd 1
2_训练主模型.cmd 2
```

不带参数时默认 seed 0。想省时间可以先用小步数验通链路（直接改 `.cmd` 里的 `--steps`，例如 2000），产物逻辑不变。

## 数据

`data/un_sub.npz`（联合国英中，60.8 万句对，字级）与 `data/opus_train.npz`（OPUS-100，60.4 万句对）随包提供，所以 `1_重建数据_可选.cmd` 默认跳过。要自己重建，先把环境变量指到原始语料再运行该文件：

```
set MPCHAIN_SRC=D:\corpus\un_pc_en-zh_0.parquet
set MPCHAIN_OPUS_SRC=D:\corpus\opus100\train-00000-of-00001.parquet
```

## 注意

- `4_` 的统计部分需要三个种子和四个消融臂的检查点；缺哪个会跳过并在屏幕上说明。
- 效率那一节（`6_`）里 batch=1 的延迟是**延迟受限**的：换更强的卡也不会变快，这一点在论文第 6.2 节有专门说明。
- 所有脚本都在本目录读写相对路径（`data/`、`evaldump/`、`ck_*.pt`），不要从别的目录调用。
